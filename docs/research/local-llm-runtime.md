# Локальный LLM-рантайм для одного хода сцены

**Дата проверки: 2026-08-21.** Исследование отвечает только на вопрос, может ли браузерная PWA выполнить на устройстве одну **реплику буллера** и/или **оценку хода** в **сцене**. Здесь «ход» — одна реплика ученика, а «оценка хода» — качество этой реплики по шкалам 0–100, согласно [глоссарию проекта](../../CONTEXT.md#измерение). Это не выбор стека, не оценка качества конкретных моделей и не описание передачи либо синхронизации весов с сервером.

Lit не меняет возможности перечисленных браузерных API. Для PWA с IndexedDB важны отдельно зафиксированные ниже механизмы кэширования: WebLLM документирует IndexedDB, Transformers.js — Cache API; Prompt API хранением модели управляет сам Chrome.

## Краткая сводка

| Рантайм | Может выполнить на устройстве реплику буллера / оценку хода | Офлайн после первичной загрузки | Мобильные браузеры | Лицензия рантайма и весов |
| --- | --- | --- | --- | --- |
| [WebLLM](https://webllm.mlc.ai/docs/) | Да: это browser-inference LLM-движок с чат-комплишенами; применимость к двум задачам зависит от выбранной модели и промпта. | Да для уже закэшированных артефактов; первая загрузка требует скачивания. | Отдельного обещания mobile support нет; требуется браузер с WebGPU. | Код WebLLM — Apache-2.0; лицензия каждой модели/весов самостоятельна. |
| [Transformers.js](https://huggingface.co/docs/transformers.js/en/index) | Да: запускает поддержанные ONNX-модели в браузере; text-generation подходит для генерации, text-classification/подобная задача — возможная форма оценки, если это поддерживает выбранная модель. | Да при доступном Cache API и сохранённых модели/WASM; первая загрузка не является офлайн-гарантией. | Отдельного обещания mobile support нет; WebGPU экспериментален во многих браузерах, но по умолчанию есть CPU/WASM-путь. | Код Transformers.js — Apache-2.0; лицензия ONNX-весов определяется карточкой конкретной модели и её базовой моделью. |
| [Chrome Prompt API / Built-in AI](https://developer.chrome.com/docs/ai/prompt-api) | Да: Prompt API посылает запрос локальной foundation-модели Chrome и возвращает текст; ограничения формата/языка и доступность проверяются до вызова. | Да, когда Chrome уже скачал модель и она не была удалена; Chrome сам управляет загрузкой, обновлением и очисткой. | Нет: Chrome для Android и iOS официально не поддерживается. | Это браузерный API и модель, которыми управляет Chrome; в проверенных документах нет отдельной лицензии на распространяемые приложением веса. |

## Что установлено официальными источниками

### WebLLM

- WebLLM выполняет LLM-инференс непосредственно в браузере через WebGPU, без серверной обработки; его `MLCEngine` предоставляет чат-комплишены. Следовательно, рантайм технически способен вернуть реплику буллера или структурированный/текстовый результат для оценки хода, если это поручено загруженной модели. [Обзор WebLLM](https://webllm.mlc.ai/docs/) и [API chat completion](https://webllm.mlc.ai/docs/user/basic_usage.html#chat-completion) документируют обе части этого утверждения.
- Для первого запуска `CreateMLCEngine`/`reload()` загружает модель асинхронно, и документация прямо предупреждает, что без прежнего кэша это может занять значительное время. [Документация загрузки модели](https://webllm.mlc.ai/docs/user/basic_usage.html#model-records-in-webllm).
- По умолчанию артефакты модели попадают в Cache API; WebLLM допускает явный backend `indexeddb`. После того как требуемые артефакты есть в этом кэше, документация описывает более быстрые последующие загрузки; Service Worker также может избежать перезагрузки модели между refresh, но браузер вправе завершить worker в любой момент. [Кэширование и IndexedDB](https://webllm.mlc.ai/docs/user/advanced_usage.html#using-indexeddb-cache), [ограничение Service Worker](https://webllm.mlc.ai/docs/user/advanced_usage.html#service-workers).
- Официальное необходимое условие — WebGPU-совместимый браузер. Документация не перечисляет поддержанные мобильные браузеры и не обещает поддержку mobile; из этого нельзя выводить работоспособность на конкретном телефоне. [Требование WebGPU](https://webllm.mlc.ai/docs/user/get_started.html#webllm-chat).
- Доступный набор предсобранных моделей — текущий `prebuiltAppConfig.model_list`; документация показывает, в частности, ID `Llama-3.1-8B-Instruct`, а также допускает модели, скомпилированные MLC-LLM. Это пример размера **8B параметров в имени модели**, а не обещание, что такая модель поместится или будет приемлемо работать на каждом устройстве. [Model records](https://webllm.mlc.ai/docs/user/basic_usage.html#model-records-in-webllm), [custom models](https://webllm.mlc.ai/docs/developer/add_models.html).
- Репозиторий WebLLM распространяет свой код под [Apache License 2.0](https://raw.githubusercontent.com/mlc-ai/web-llm/main/LICENSE). Эта лицензия относится к рантайму, а не автоматически к весам: лицензию конкретной выбранной модели нужно проверять в её model card/лицензии.

### Transformers.js

- Transformers.js запускает поддержанные модели в браузере через ONNX Runtime. По умолчанию браузерный запуск использует CPU через WASM; GPU задействуется только при `device: "webgpu"`. Это даёт два документированных способа исполнить локальную генерацию реплики буллера или локальную модельную оценку хода. [Обзор и пример WebGPU](https://huggingface.co/docs/transformers.js/en/index), [руководство WebGPU](https://huggingface.co/docs/transformers.js/en/guides/webgpu).
- Поддерживаются разные задачи и архитектуры, а совместимые модели ищутся по тегу `transformers.js`; поддержка конкретной задачи не следует из одного только имени модели. Для генерации документация приводит `onnx-community/Qwen2.5-0.5B-Instruct` с `text-generation`; его карточка говорит, что это ONNX-веса, совместимые с Transformers.js. [Список задач/моделей](https://huggingface.co/docs/transformers.js/en/index#supported-tasksmodels), [пример text-generation и dtype](https://huggingface.co/docs/transformers.js/en/guides/dtypes), [карточка ONNX-модели](https://huggingface.co/onnx-community/Qwen2.5-0.5B-Instruct).
- Практическое ограничение размера выбирается моделью и вариантом точности: доступность `fp32`, `fp16`, `q8`, `q4` зависит от модели. В качестве масштаба, не как рекомендация, карточка базовой `Qwen2.5-0.5B-Instruct` указывает **0,49B параметров**; её ONNX-вариант содержит несколько квантованных файлов. [Правила выбора dtype](https://huggingface.co/docs/transformers.js/en/guides/dtypes), [карточка базовой модели](https://huggingface.co/Qwen/Qwen2.5-0.5B-Instruct), [состав ONNX-варианта](https://huggingface.co/onnx-community/Qwen2.5-0.5B-Instruct/tree/main).
- В браузере `useBrowserCache` по умолчанию включён при наличии Cache API; `useWasmCache` также включается при доступном кэше и документация прямо связывает его с офлайн-использованием без повторных загрузок. Это подтверждает офлайн-выполнение после сохранения нужных файлов, но не гарантирует их наличие или неограниченное хранение. [Параметры browser/WASM cache](https://huggingface.co/docs/transformers.js/en/api/env).
- WebGPU всё ещё экспериментален во многих браузерах, и официальное руководство не даёт отдельной гарантии мобильной поддержки. CPU/WASM — документированный fallback по умолчанию, но фактическая работоспособность и скорость для модели остаются свойствами браузера, памяти и выбранных файлов. [Ограничение WebGPU](https://huggingface.co/docs/transformers.js/en/index), [совместимость WebGPU](https://huggingface.co/docs/transformers.js/en/guides/webgpu).
- Код Transformers.js лицензирован по [Apache License 2.0](https://raw.githubusercontent.com/huggingface/transformers.js/main/LICENSE). Это не лицензия весов: например, у ONNX-карточки выше указан `base_model` `Qwen/Qwen2.5-0.5B-Instruct`, а базовая модель опубликована под [Apache-2.0](https://huggingface.co/Qwen/Qwen2.5-0.5B-Instruct/blob/main/LICENSE). Для другого репозитория модели условия могут отличаться и должны проверяться по его карточке.

### Chrome Prompt API / Built-in AI

- Prompt API отправляет natural-language запрос foundation-модели в Chrome; документация называет используемую модель Gemini Nano. Модель отделена от API и скачивается при первом использовании origin, а готовность следует проверять через `LanguageModel.availability()`. Поэтому API может выполнить локальную реплику буллера либо текстовую/схемную оценку хода, когда `availability()` допускает создание сессии. [Prompt API: модель, загрузка и availability](https://developer.chrome.com/docs/ai/prompt-api#use-the-prompt-api).
- Размер не фиксирован: Chrome пишет, что точный размер Gemini Nano меняется с обновлениями. Отдельно управление моделью документирует выбор варианта, например **4B** или **2B параметров**, по производительности устройства либо CPU fallback; JavaScript не даёт узнать версию модели программно. [Размер и требования](https://developer.chrome.com/docs/ai/prompt-api#review-the-hardware-requirements), [варианты и обновления](https://developer.chrome.com/docs/ai/understand-built-in-model-management).
- Официальные требования для API с foundation-моделями: не менее 22 GB свободного места; Windows 10/11, macOS 13+, Linux или Chromebook Plus; GPU с более чем 4 GB VRAM либо CPU с не менее чем 16 GB RAM и 4 ядрами. Это требования Chrome, а не benchmark времени одного хода. [Требования Prompt API](https://developer.chrome.com/docs/ai/prompt-api#review-the-hardware-requirements).
- После загрузки Chrome документирует офлайн-использование built-in AI. Однако это условно: Chrome автоматически обновляет и может удалить модель из-за свободного места, enterprise policy или потери eligibility; API, доступный в начале сцены, может стать недоступным позднее. [Офлайн-свойство Built-in AI](https://developer.chrome.com/docs/ai/built-in/overview#benefits-of-running-client-side), [удаление модели](https://developer.chrome.com/docs/ai/understand-built-in-model-management#model-deletion).
- Для Prompt API официально не поддерживаются Chrome для Android и iOS, а доступность ограничена Chrome на Windows, macOS и Linux (страница overview также упоминает Chrome Extensions). Следовательно, это явное ограничение для мобильной PWA, а не отсутствие теста. [Поддерживаемые ОС и исключённые mobile-платформы](https://developer.chrome.com/docs/ai/prompt-api#review-the-hardware-requirements), [обзор доступности](https://developer.chrome.com/docs/ai/built-in/overview#benefits-of-running-client-side).
- Prompt API пока недоступен в Web Workers. Также заявленные языки `expectedInputs`/`expectedOutputs` в этой версии ограничены `en`, `ja`, `es`, `de`, `fr`; русский не указан. Это ограничение API надо учитывать отдельно от способности Gemini Nano генерировать текст. [Workers](https://developer.chrome.com/docs/ai/prompt-api#permission-policy-iframes-and-web-workers), [список языков](https://developer.chrome.com/docs/ai/prompt-api#add-expected-input-and-output).
- Chrome позиционирует Built-in AI как API, где браузер сам распределяет и управляет моделью; в проверенных официальных страницах не опубликована отдельная лицензия на веса, которую PWA могла бы выбрать или включить в дистрибутив. Поэтому лицензию Chrome Prompt API нельзя приравнивать к Apache-2.0 у двух JavaScript-рантаймов. [Модель управляется браузером](https://developer.chrome.com/docs/ai/built-in/overview#benefits-of-built-in-ai-for-web-developers).

## Что зависит от модели и устройства

Следующие выводы **не гарантированы** документациями рантаймов и требуют проверки выбранных модели, файлов и целевых устройств:

- Будет ли конкретная модель приемлемо воспроизводить реплику буллера на русском и давать устойчивую оценку хода по шкалам 0–100; рантаймы документируют исполнение, а не качество или безопасность результата. Поддержка задач и моделей у Transformers.js отдельно вариативна, а WebLLM использует текущий список model records. [Transformers.js: supported tasks/models](https://huggingface.co/docs/transformers.js/en/index#supported-tasksmodels), [WebLLM: model records](https://webllm.mlc.ai/docs/user/basic_usage.html#model-records-in-webllm).
- Поместятся ли модель и её KV-cache в доступную память, будет ли доступен WebGPU и сколько займёт один ход. WebLLM прямо предоставляет сведения о максимальном GPU storage buffer для более крупных моделей; Transformers.js предупреждает об экспериментальном WebGPU. Официальные источники не устанавливают benchmark или универсальные минимальные требования для WebLLM/Transformers.js. [WebLLM GPU information](https://webllm.mlc.ai/docs/user/api_reference.html#gpu-information), [Transformers.js WebGPU warning](https://huggingface.co/docs/transformers.js/en/index).
- Какие именно весовые файлы и квантизация доступны, их объём и лицензия. Например, перечисленный ONNX-репозиторий имеет q4/fp16/int8 варианты, но это не делает такие варианты обязательными для других моделей; условия использования нужно брать из карточки и лицензии выбранных весов. [Пример ONNX-файлов](https://huggingface.co/onnx-community/Qwen2.5-0.5B-Instruct/tree/main), [лицензия примера базовой модели](https://huggingface.co/Qwen/Qwen2.5-0.5B-Instruct/blob/main/LICENSE).
- Сохранятся ли уже загруженные данные: WebLLM и Transformers.js опираются на браузерные кэши, а Chrome может удалить встроенную модель. В PWA IndexedDB применим как документированный backend WebLLM, но это не превращает сохранность браузерного хранилища в гарантию рантайма. [WebLLM IndexedDB](https://webllm.mlc.ai/docs/user/advanced_usage.html#using-indexeddb-cache), [Transformers.js cache](https://huggingface.co/docs/transformers.js/en/api/env), [Chrome purge](https://developer.chrome.com/docs/ai/understand-built-in-model-management#model-deletion).
