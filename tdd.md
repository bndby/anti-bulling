# AI Anti-Bullying Trainer

## Vision

Создать PWA-приложение, которое с помощью LLM обучает детей 10–16 лет уверенно и безопасно реагировать на буллинг.

Это **не чат-бот**.

Это полноценный AI-симулятор школьной жизни.

По сложности и вовлеченности он должен напоминать Duolingo + RPG + Character.ai.

Основная идея:

> ребенок не читает советы.

Он многократно проживает конфликтные ситуации.

---

# Главная цель

После 100-200 тренировок ребенок должен автоматически:

* не теряться;
* не оправдываться;
* не отвечать агрессией;
* спокойно защищать свои границы;
* понимать намерения буллера;
* меньше бояться социальных конфликтов.

---

# Основные принципы

Приложение никогда

* не поощряет насилие;
* не предлагает месть;
* не учит унижать других.

Оно обучает

* уверенности;
* эмоциональной устойчивости;
* ассертивности;
* эмпатии;
* деэскалации.

# System Prompt Bully

Буллер НЕ должен

быть карикатурным.

Он должен вести себя как настоящий подросток.

Не использовать взрослую лексику.

Постепенно менять стратегию.

Если ребенок отвечает уверенно —

искать другой способ давления.

Если ребенок растерялся —

не становиться сразу злым.

Буллер должен быть психологически правдоподобным.

# Safety

Запрещено

романтизировать буллинг

поощрять месть

оскорблять ребенка

газлайтить

угрожать

побуждать к опасным действиям

Если пользователь сообщает о реальном продолжающемся буллинге, угрозах насилия или мыслях о причинении вреда себе или другим, приложение должно прекратить тренировку, перейти в режим поддержки, мягко рекомендовать обратиться к доверенному взрослому (родителю, учителю, школьному психологу) и предоставить соответствующие ресурсы помощи, а не продолжать симуляцию.

## Дополнительные рекомендации для Cursor

* Пиши код как production-grade проект, а не демонстрационный пример.
* Используй feature-first архитектуру и строгую типизацию TypeScript.
* Все AI-взаимодействия должны проходить через единый абстрактный `AIService`, чтобы можно было заменить поставщика модели без изменения бизнес-логики.
* Все промпты должны храниться как отдельные Markdown-файлы с шаблонами и параметрами, а не в виде строк в коде.
* Проектируй приложение так, чтобы новые сценарии, персонажи и механики добавлялись декларативно через JSON/Markdown, без изменения исходного кода.
* Каждая новая функция должна сопровождаться тестами и краткой документацией.
* Интерфейс должен быть дружелюбным для детей: минимум текста на экране, крупные элементы управления, понятные иллюстрации и плавные анимации без визуальной перегрузки.

Для действительно масштабной системы следующей ступенью я бы сделал отдельные спецификации для **AI-агентов**, **библиотеки из нескольких сотен сценариев** и **набора системных промптов** — именно они определят качество обучения больше, чем сам интерфейс.
